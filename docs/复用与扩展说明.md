# 复用与扩展说明（面向第 2—8 个课件）

本仓库把“页面”和“内容”彻底分开：页面组件只负责渲染与交互，全部学科知识以数据形式存放在 `src/content/`。
因此新增一个课件 = 新增一个内容目录 + 注册一行，**不需要复制页面代码**。

## 一、五步接入新课件

```text
1) 复制     src/content/antigen/  →  src/content/<新课程id>/
2) 改写     四个数据文件（见下表）
3) 注册     src/content/index.ts 里新增 bundle，并把 activeCourse 指向它
4) 补充     若需要新的可视化：新增 VisualKey + 在 ModuleVisual.tsx 登记
5) 验证     npm run typecheck && npm run build && npm run e2e
```

| 文件 | 作用 | 必填 |
|---|---|---|
| `course.ts` | 课程元信息、导航、首页分区、学习路径、知识图谱、课前学习 | 是 |
| `modules.ts` | 模块正文（小节、要点、可视化 key、随堂小测 id） | 是 |
| `questions.ts` | 题库（单选/多选/判断/排序/分类/开放），按分组导出 | 是 |
| `extras.ts` | 案例、作业分层、评价维度、课程思政、学科前沿、术语表、任务清单 | 是 |

## 二、可复用组件清单（已抽象）

| 组件 | 位置 | 复用方式 |
|---|---|---|
| 首页主题模板 | `pages/Home.tsx` + `course.ts` | 换 `course` 数据即可；Hero/图谱/路径/预览/案例/互动入口全部数据驱动 |
| 学习目标组件 | `components/learn.tsx` → `LearningObjectives` | 传入 `course.objectives` |
| 知识图谱 | `components/learn.tsx` → `KnowledgeGraph` | 传 `course.graph`（节点 + 连线），自动布局 |
| 学习路径 | `components/learn.tsx` → `PathTimeline` | 传 `course.pathway`，自动读取访问状态 |
| 三维模型查看器 | `three/ModelViewer.tsx` | 传一个 `SceneFactory`（返回 `scene/camera/parts/toggles/fit`） |
| 三维场景 | `three/create*.ts` | 复制后改几何与部件文案；`fit.radius` 控制自动取景 |
| 分步动画播放器 | `components/StepPlayer.tsx` | 传 `steps` + `render(active)`，自带播放/暂停/重播/变速/跳步 |
| 图示组件 | `components/visuals.tsx` | 每个图示独立、无页面依赖，可直接搬到新章节 |
| 题目组件 | `components/quiz.tsx` | 按 `Question` 类型渲染，自动判分与解析回链 |
| 学习进度 | `components/progress.tsx` | `useProgress` / `useStats`；换课程时可改 `STORAGE_KEY` 隔离 |
| 案例组件 | `pages/Cases.tsx` + `TeachingCase` | 四段式结构与真实性声明为通用模板 |
| 课后评价 | `pages/Assessment.tsx` + `AssessmentDimension[]` | 维度、权重、判据全部数据化 |
| 二维码组件 | `pages/QrShare.tsx` + `scripts/make-qr.mjs` | 运行时生成 + 静态 PNG/SVG 双路径 |

## 三、新增可视化 / 三维模型的约定

```ts
// 1) 在 content/types.ts 的 VisualKey 联合类型里加一个 key
// 2) 在 components/ModuleVisual.tsx 的 switch 里登记组件
// 3) 组件的输入要尽量少（状态内部管理），便于在不同章节复用
```

```ts
// 三维场景约定：必须返回 ViewerScene
export const createXxxScene: SceneFactory = ({ lowPower, reducedMotion }) => {
  const scene = baseScene()          // 统一光照
  const camera = makeCamera(7)       // 初始机位（会被 fit 覆盖）
  // ... 程序化建模 ...
  return assemble(scene, camera, parts, {
    fit: { radius: 2.8 },            // 包围球半径：保证任意屏幕比例不裁切
    toggles: [{ id: 'x', label: '显隐X', on: true }],
    setToggle: (id, on) => { /* ... */ },
    update: (elapsed, delta) => { /* 可选逐帧动画 */ },
  })
}
```

要求：
- 只用 Three.js 基础几何 + 程序化生成，**不引入外部模型/贴图**（避免版权、体积与加载失败风险）；
- `parts` 的 `label` 必须是准确的中文专业术语，`detail` 要说清“这是哪一类抗原”；
- 低性能设备（`lowPower`）走低多边形分支；
- 必须提供 WebGL 不可用时的静态替代内容。

## 四、隔离与共存

- **一课程一仓库**（推荐，最简单）：每个课件单独部署，地址独立，二维码各自生成；
- **多课程一站点**：把路由改为 `/:courseId/...`，`activeCourse` 由路由参数决定；进度存储 key 加课程前缀；
- 无论哪种方式，都不要为“未开发的章节”创建空壳页面或导航项。

## 五、发布前检查（每个课件都适用）

```bash
npm run typecheck
npm run build
npm run preview:test &   # 另开终端
npm run e2e
npm run qr -- https://<正式地址>/
# 再按 docs/匿名化检查报告.md 第三节逐项确认
```
