### 为什么用 gh-pages 分支而不是 GitHub Actions

部署时发现当前账号的 Personal Access Token **未授予 `workflow` scope**，因此无法推送 `.github/workflows/` 下的文件
（GitHub 拒绝：`refusing to allow a Personal Access Token to create or update workflow ... without workflow scope`）。

改用 Pages 的 **Deploy from a branch** 模式：把构建产物推到 `gh-pages` 分支根目录即可，功能等价，且不依赖 CI 权限。
原 Actions 配置保留在 `docs/templates/deploy-actions.yml`，日后若要恢复自动化：

```bash
mv docs/templates/deploy-actions.yml .github/workflows/deploy.yml
# 并在 GitHub Settings → Pages → Source 改为 "GitHub Actions"
```

## 二、更新内容的标准流程

```bash
npm run build      # 类型检查 + 构建
npm run publish    # 把 dist/ 推到 gh-pages 分支（一条命令完成发布）
```

`npm run publish` 会自动：
- 复制 `dist/` 到临时目录
- 写入 `.nojekyll`（静态托管必需，否则下划线开头文件会被 Jekyll 忽略）
- 以中性身份 `course-maintainer` 提交并强制推送 `gh-pages`

**地址保持不变**，所以已印制的二维码无需更换。

## 四、二维码可用性说明（如实告知，不承诺永久）

二维码本身不含过期时间，但它指向的地址必须持续可用。**失效条件**：

1. 仓库被删除、转为私有、或改名；
2. GitHub 账号受限、组织被解散；
3. GitHub Pages 服务关闭或策略变更；
4. 若日后绑定自定义域名且域名到期 / DNS 失效。

**重新部署内容不会改变地址**，二维码继续有效。若上述任一情况发生，需
`npm run qr -- <新地址>` 重新生成并替换已印制材料。
